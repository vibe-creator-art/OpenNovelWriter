## Purpose
总结当前场景，按需更新已有词条的经历和关系，并把本场同步进 Story State。

## When to use
用户写完一场、或要求总结当前章节并更新设定时使用。只处理当前这场。

## Instructions

### 1. 总结场景
把用户给定的当前章节提炼成简明浓缩版本，用 `update_scene_summary` 写入。先写摘要，再做后面两步。

总结时严格遵守：
1. 字数与语言：总字数约 150–200，误差 10% 可接受。必须使用中文的拼写、语法和语言习惯。
2. 格式纯粹：只输出连贯纯文本段落，不要 markdown、列表或 bullet。不要「在这个场景中……」「以下是……」这类开场白，直接写总结正文。
3. 称呼与视角：
   - 统一第三人称、现在时。
   - 直接用角色姓名，不要用身份或头衔指代。
   - 极力避免代词（他、她、他们等），用具体姓名替换。
   - 假设读者已了解角色档案和世界观，不要解释某人或某地是谁。
4. 时空与段落：交代事件发生的时间和地点。过程过长，或发生重大时间/地点转换时，另起一段。
5. 只保留核心剧情：
   - 不要提背景故事（前文总结已包含）。日常琐事、无名背景人物除非对推进至关重要，否则不写。只有被指名道姓的角色或地点才有记录价值。
   - 不要内心独白或反思。省略感官细节、环境描写和具体对话过程，只提取实质性进展。
   - 中立客观，不添加评论、情感色彩或对后续的预测。
6. 只有极其必要时才查前文帮助总结，一般情况下不需要。

优秀总结与糟糕总结的对比：
- 对比 1（去流水账，强调冲突，不用代词）
  - <bad>林羽遇到了苏雪，他们在客栈喝茶，后来一起去拜访了长老。</bad>
  - <good>在云烟客栈，林羽和苏雪因争夺[某件法宝]发生争执。随后赵无极出现，强行将林羽和苏雪带往宗门大殿。</good>
- 对比 2（把漫无目的的动作变成具体目标）
  - <bad>林羽走过魔兽森林，四处寻找赵无极复仇。</bad>
  - <good>在魔兽森林中，林羽试图布下杀阵以伏击赵无极。</good>
- 对比 3（压缩对话，提取信息，杜绝代词）
  - <bad>他们一边打坐吐纳，林羽一边谈论苏雪以及他们准备探索上古秘境的计划。</bad>
  - <good>林羽和苏雪商议探索上古遗迹的后续策略。</good>

### 2. 更新词条经历和关系
用户已经准备好词条，只更新已有词条，可在 `novel/terms` 查看。不要新建词条。

不是每个出场人物/物品都要改。只有重大经历、关系变动、或后文需要记住的内容才写入。琐碎事情不记。没必要更新就跳过，不要为了更新而更新。经历一行一条，短句，不要写复杂。

### 3. 同步故事状态
`update_scene_summary` 成功后再入图。先读内置 `story-state` 技能。空摘要无法同步。不要为入图去改摘要或正文。其他过期来源交给「预设-修复过期来源」，不要顺手全库大修。

词条经历从简；账本可以更细，记录位置、持有、状态、关系等后文需要守住的命题。抽到的实体不要升级成词条。

1. 从 `novel/outline.md` 取 `novel_id`。用带 `query` / `entityId` 的 `query_story_state` 按本场出现的名字查已有实体和相关 Fact。不要只传 `novelId` 拉全图。
2. 复用已有 Entity / Alias / Fact。同名先查再写，不要因措辞变化新建。称谓、简称用 `add_story_entity_alias`（抽取用 `EXTRACTED`）。本场需要入账但还没有实体的，用 `upsert_story_entity` 创建；不要因此 `create_term`。
3. 只在摘要里有明确时间锚点、状态转折、或必须表达先后时才创建 Moment。一场可以是 0、1 或多个。创建时只传自然语言 `label` 和可选 `afterMomentId`，不要提交整数顺序。
4. 从已保存的场景摘要抽取 Fact，调用 `sync_scene_story_episode`。`predicateKey` 用稳定大写键（如 `LOCATED_AT`、`OWNS`、`STATUS`、`KNOWS`）。新 Fact 必须能从摘要直接读出，不要把推测写成确定事实；实体宾语优先 `objectEntityId`。含义已存在的 Fact 只传 `factId` 续挂。故事世界里状态真的变了，才用 `closeFacts` 关掉旧 Fact，并写从该 Moment 生效的新 Fact。
5. 若本场已有来源：摘要刚被本技能重写则按新摘要抽取，仍成立的旧命题传 `factId`，新摘要不再支持的不要 copy-forward。hash 未变则工具会跳过，不要强行再写。不要对场景来源使用 `retract_story_episode` 或 `assert_story_facts`。

## Output
用几句话说明：摘要已写入；更新了哪些词条（或无需更新）；入图时新建/复用了哪些实体，以及是否创建了 Moment。不要默认列出全部 Fact。
