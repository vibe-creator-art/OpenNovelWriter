## Purpose
总结当前场景，并按需更新已有词条的经历和关系。

## When to use
用户写完一场、或要求总结当前章节并更新词条时使用。只处理当前这场。不写入 Story State。

## Instructions

### 1. 总结场景
把用户给定的当前章节提炼成简明浓缩版本，用 `update_scene_summary` 写入。先写摘要，再更新词条。

总结时严格遵守：
1. 字数与语言：总字数约 150–200，误差 10% 可接受。必须使用中文的拼写、语法和语言习惯。
2. 格式纯粹：只输出连贯纯文本段落，不要 markdown、列表或 bullet。不要「在这个场景中……」「以下是……」这类开场白，直接写总结正文。
3. 称呼与视角：
   - 统一第三人称、现在时。
   - 直接用角色姓名，不要用身份或头衔指代。
   - 极力避免代词（他、她、他们等），用具体姓名替换。
   - 假设读者已了解角色档案和世界观，不要解释某人或某地是谁。
4. 时空与段落：交代事件发生的时间和地点。过程过长，或发生重大时间/地点转换时，另起一段。
5. 只保留核心剧情：
   - 不要提背景故事（前文总结已包含）。日常琐事、无名背景人物除非对推进至关重要，否则不写。只有被指名道姓的角色或地点才有记录价值。
   - 不要内心独白或反思。省略感官细节、环境描写和具体对话过程，只提取实质性进展。
   - 中立客观，不添加评论、情感色彩或对后续的预测。
6. 只有极其必要时才查前文帮助总结，一般情况下不需要。

优秀总结与糟糕总结的对比：
- 对比 1（去流水账，强调冲突，不用代词）
  - <bad>林羽遇到了苏雪，他们在客栈喝茶，后来一起去拜访了长老。</bad>
  - <good>在云烟客栈，林羽和苏雪因争夺[某件法宝]发生争执。随后赵无极出现，强行将林羽和苏雪带往宗门大殿。</good>
- 对比 2（把漫无目的的动作变成具体目标）
  - <bad>林羽走过魔兽森林，四处寻找赵无极复仇。</bad>
  - <good>在魔兽森林中，林羽试图布下杀阵以伏击赵无极。</good>
- 对比 3（压缩对话，提取信息，杜绝代词）
  - <bad>他们一边打坐吐纳，林羽一边谈论苏雪以及他们准备探索上古秘境的计划。</bad>
  - <good>林羽和苏雪商议探索上古遗迹的后续策略。</good>

### 2. 更新词条经历和关系
用户已经准备好词条，只更新已有词条，可在 `novel/terms` 查看。不要新建词条。

不是每个出场人物/物品都要改。只有重大经历、关系变动、或后文需要记住的内容才写入。琐碎事情不记。没必要更新就跳过，不要为了更新而更新。经历一行一条，短句，不要写复杂。

## Output
用几句话说明：摘要已写入；更新了哪些词条（或无需更新）。
